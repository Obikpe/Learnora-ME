# Lesson 19: Writing Strong Case Studies

## Learning outcomes
Apply the professional practice, produce a project artefact and communicate decisions with evidence.

## 1. Core explanation
A case study tells the story of a project through problem, evidence, method, result and limitations. Start with the decision or question, then explain why it matters. Describe the data source, coverage and preparation. Explain the method in enough detail for a technical reader to assess it, but avoid turning the case study into a list of code cells.

Show the result with one or two clear visuals and explain what the numbers mean. State your individual contribution, especially for team projects. Include unsuccessful approaches when they teach something important. Distinguish completed work from planned extensions.

A credible case study includes limitations and next steps. Do not overstate model accuracy, imply causality from observational data or hide inconvenient findings. Link to the repository and reproducible artefacts where possible.

## 2. Worked example or template
Use the example as a starting point and adapt it to your own project. Python examples run in VS Code; shell commands should be entered in the VS Code terminal.

```python
case_study = [
    "Problem: what decision or question?",
    "Context: why does it matter?",
    "Data: source, scope, licence and quality",
    "Method: cleaning, analysis and modelling",
    "Evidence: results, metrics and visuals",
    "Contribution: what I personally did",
    "Limitations: what the work cannot establish",
    "Next steps: what further evidence is needed"
]
print("\n".join(case_study))
```

## 3. Professional application
Keep claims evidence-based. Document sources, assumptions, licences, decisions and limitations. A portfolio project should be understandable and reproducible without access to private data or undocumented local files.

## 4. Guided practice
Write a case study for one completed project using this structure. Ask a technical reviewer to identify one unsupported claim and one missing methodological detail.

## 5. Independent practice
Create or improve the corresponding project artefact in your repository. Ask another person to review it and record what was unclear or incomplete.

## 6. Knowledge check

2. What evidence should be preserved?
3. Which risks or constraints need to be disclosed?
