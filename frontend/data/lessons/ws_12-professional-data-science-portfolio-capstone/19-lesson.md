# Lesson 19: Writing Strong Case Studies

## Learning outcomes
Apply the professional practice, produce the capstone artefact and communicate evidence and limitations clearly.

## 1. Core explanation
A case study tells the story of a project through the problem, evidence, method, result and limitations. Start with the decision or question, then explain why it matters. Describe the data source, coverage and preparation. Explain the method in enough detail for a technical reader to assess it, but avoid turning the case study into a list of code cells.

Show the result with one or two clear visuals and explain what the numbers mean. State your individual contribution, especially for team projects. Include unsuccessful approaches when they teach something important. Distinguish completed work from planned extensions.

A credible case study includes limitations and next steps. Do not overstate model accuracy, imply causality from observational data or hide inconvenient findings. Link to the repository and reproducible artefacts where possible.

## 2. Worked example or template
Run the Python example in VS Code where applicable. Adapt paths and fields to your own dataset; do not publish restricted records.

```python
case_study = [
    "Problem: what decision or question?",
    "Context: why does it matter?",
    "Data: source, scope, licence and quality",
    "Method: cleaning, analysis and modelling",
    "Evidence: results, metrics and visuals",
    "Contribution: what I personally did",
    "Limitations: what the work cannot establish",
    "Next steps: what further evidence is needed"
]
print("\n".join(case_study))
```

## 3. Capstone application
Maintain a decision log and connect every analysis step to the project charter. Preserve provenance and reproducibility. Separate observed results from interpretation and recommendations.

## 4. Guided practice
Write a case study for one completed project using this structure. Ask a technical reviewer to identify one unsupported claim and one missing methodological detail.

## 5. Independent practice
Complete the corresponding capstone deliverable. Ask a reviewer to reproduce or challenge one result and record the changes made in response.

## 6. Knowledge check
1. What evidence does this deliverable provide?
2. Which assumptions or limitations affect the conclusion?
3. How can another person reproduce the work?
4. What is the next responsible action?

## Lesson summary
A capstone demonstrates an end-to-end professional process: a well-framed question, defensible data, reproducible analysis, validation, clear communication and responsible publication.
