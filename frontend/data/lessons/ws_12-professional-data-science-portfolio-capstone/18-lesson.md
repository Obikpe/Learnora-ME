# Lesson 18: Selecting and Positioning Portfolio Projects

## Learning outcomes
Apply the professional method, produce a project artefact and communicate decisions with evidence.

## 1. Core explanation
A strong portfolio demonstrates breadth and depth. Select projects that show different capabilities: data cleaning and SQL, exploratory analysis and visualisation, statistical reasoning, supervised or unsupervised modelling, and an applied end-to-end workflow. Do not include several projects that all demonstrate the same small skill.

Choose projects with a clear question, credible data source, defensible methods and a useful output. A small, well-explained project is stronger than a large notebook with no interpretation. Include realistic constraints and limitations. If a project is ongoing, label it as such and state what is complete and what remains.

Position projects for the role you want. A data analyst portfolio should foreground data quality, SQL, dashboards and business interpretation. A data science portfolio should also show validation, model selection and error analysis. Explain the skill demonstrated rather than listing every library used.

## 2. Worked example or template
Use the example in VS Code or adapt the structure to your project.

```python
project_matrix = [
    {"project": "Customer analysis", "skills": "SQL, cleaning, segmentation"},
    {"project": "Operations dashboard", "skills": "visualisation, KPI design"},
    {"project": "Churn prediction", "skills": "classification, evaluation"},
    {"project": "Text grouping", "skills": "NLP, clustering"}
]
for p in project_matrix:
    print(p["project"], "->", p["skills"])
```

## 3. Professional application
Keep the artefact reproducible and honest. State the data source, time period, methods, your contribution and limitations. Do not publish confidential data or make unsupported performance claims.

## 4. Guided practice
Select three projects for a target job. Map each project to a job requirement and explain what evidence proves the skill. Identify one project you would remove and why.

## 5. Independent practice
Create or improve the corresponding project artefact. Ask another person to review it and record any unclear assumptions or missing instructions.

## 6. Knowledge check
1. What decision or audience does this artefact serve?
2. What evidence supports the claim?
3. Which limitations must be disclosed?
4. How can another person verify the work?

## Lesson summary
A professional portfolio demonstrates judgement, evidence, reproducibility and communication—not just familiarity with tools.
