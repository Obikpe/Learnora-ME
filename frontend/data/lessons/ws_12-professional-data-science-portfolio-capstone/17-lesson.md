# Lesson 17: Designing a Portfolio Website

## Learning outcomes

By the end of this lesson, you should be able to Plan a portfolio website structure that makes target role, projects, demonstrated skills, professional background, CV and contact information easy to find; and protect private data.

## 1. Core explanation
A portfolio website is a navigation layer for selected evidence, not a replacement for the projects themselves. It should make the audience, skills, project outcomes and contact route clear. Prioritise readability, mobile responsiveness, accessibility, fast loading and working links. Avoid excessive animation or vague claims.

Each project page should answer: what problem was addressed, what data was used, what work you personally completed, which methods were applied, what result was achieved and what limitations remain. Link to code, reports or demos where safe. Do not publish confidential client data or credentials.

A portfolio should be maintained. Check links, screenshots, dependencies and project descriptions regularly. Distinguish completed projects from work in progress. Use honest language about your role and contribution.

## 2. Worked example or template
Use the example in VS Code or adapt the structure to your project.

```python
portfolio_sections = [
    "Introduction and target role",
    "Selected projects with outcomes",
    "Technical skills demonstrated by evidence",
    "About and professional background",
    "CV or resume",
    "Contact details"
]
print("\n".join(portfolio_sections))
```

## 3. Professional application
Keep the artefact reproducible and honest. State the data source, time period, methods, your contribution and limitations. Do not publish confidential data or make unsupported performance claims.

## 4. Guided practice
Sketch a simple portfolio sitemap and write the content hierarchy for a project page. Explain how a recruiter can verify your contribution without exposing private data.

## 5. Independent practice
Create or improve the corresponding project artefact. Ask another person to review it and record any unclear assumptions or missing instructions.

## 6. Knowledge check
1. What decision or audience does this artefact serve?
2. What evidence supports the claim?
3. Which limitations must be disclosed?
