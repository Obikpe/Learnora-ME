# Lesson 15: Visual Communication and Reporting

## Learning outcomes
Apply the professional method, produce a project artefact and communicate decisions with evidence.

## 1. Core explanation
A report should guide the reader from question to evidence to implication. Use headings that communicate the argument, not generic labels. Visuals need informative titles, units, readable scales and source notes. Avoid unnecessary decoration, 3-D effects and misleading axis ranges.

Use one primary message per chart. Add annotations only when they clarify an important point. Include sample size, time period and denominator. Put technical details and secondary analysis in an appendix so that the main report remains focused without hiding important caveats.

A strong report distinguishes facts, interpretations and recommendations. Label assumptions and uncertainty. Do not imply causality from correlation or generalise beyond the sample. Make the next decision explicit and explain what additional evidence would change the recommendation.

## 2. Worked example or template
Use the example in VS Code or adapt the structure to your project.

```python
report_sections = [
    "Executive summary: decision and key finding",
    "Question and context: population and time window",
    "Data: source, definitions and limitations",
    "Method: analysis and validation",
    "Results: visuals and measured evidence",
    "Interpretation: what the evidence means",
    "Limitations and risks",
    "Recommendation and next steps"
]
for section in report_sections:
    print("-", section)
```

## 3. Professional application
Keep the artefact reproducible and honest. State the data source, time period, methods, your contribution and limitations. Do not publish confidential data or make unsupported performance claims.

## 4. Guided practice
Create a three-page report outline for an analysis project. Identify the single most important chart, its message, its denominator and one caveat that must appear beside it.

## 5. Independent practice
Create or improve the corresponding project artefact. Ask another person to review it and record any unclear assumptions or missing instructions.

## 6. Knowledge check
1. What decision or audience does this artefact serve?
2. What evidence supports the claim?
3. Which limitations must be disclosed?
4. How can another person verify the work?
