# Lesson 25: Working with Stakeholders and Feedback

## Learning outcomes
Apply the professional practice, produce a project artefact and communicate decisions with evidence.

## 1. Core explanation
Stakeholder work begins with listening and clarifying. Different stakeholders may use the same word differently: active customer, completed course or late delivery needs a shared definition. Confirm assumptions in writing and show early outputs to catch misunderstandings before the project is complete.

Feedback is information, not an instruction to manipulate results. Separate requests that clarify the question from requests that would misrepresent evidence. Explain trade-offs respectfully and document agreed changes. If a stakeholder asks for an unsupported conclusion, present what the data can show and what further analysis would be required.

Maintain a decision log and versioned deliverables. Summarise meetings with actions, owners and dates. Good communication reduces rework and helps the analytical result become useful in practice.

## 2. Worked example or template
Use the example as a starting point and adapt it to your own project. Python examples run in VS Code; shell commands should be entered in the VS Code terminal.

```python
meeting_note = {
    "decision_question": "Which regions need service improvement?",
    "definition_confirmed": "Complaint rate per 1,000 completed orders",
    "data_owner": "Operations",
    "open_issue": "Two regions have incomplete order counts",
    "action": "Operations to confirm denominator by Friday"
}
print(meeting_note)
```

## 3. Professional application
Keep claims evidence-based. Document sources, assumptions, licences, decisions and limitations. A portfolio project should be understandable and reproducible without access to private data or undocumented local files.

## 4. Guided practice
Prepare a stakeholder clarification checklist for a dashboard request. Include metric definitions, filters, refresh frequency, intended decisions, access permissions and acceptance criteria.

## 5. Independent practice
Create or improve the corresponding project artefact in your repository. Ask another person to review it and record what was unclear or incomplete.
